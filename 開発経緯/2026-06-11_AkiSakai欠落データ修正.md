# 2026-06-11 Aki Sakai欠落データ調査・maxRows修正

## Jamieからの報告

> An example of missing data occurred on Monday 8th June for Aki Sakai(BS).
> She did 9 starts between 2.40pm and 4.30pm.
> Only 2 are displaying in the web app.

## 調査結果

### DB データ確認
- user_id=142, transponder TX-19115
- 6/8 14:40-16:30 JST の passings: 150行
- 位置別: FP=19, 0m=19, 60m=18, AP1=18, 50m=18, 100m=14, BP=14, 200m=11, 150m=10, AP2=9
- SB1(user_id空): 39行

### パイプライン実行結果
- **webapp split_laps**: 19ラップ生成（正常）
- **legacy split_laps**: 19ラップ生成（webapp と完全一致）

### データ構造の理解
各「スタート」は2ラップで構成される:
1. **Standing start lap** (SB1=Y, FP=N): スタートブロックから0mまで
2. **Flying lap** (SB1=N, FP=Y): FPから次の0mまでの周回

9スタート × 2ラップ = 18ラップ + 1追加 = 19ラップ

### 真の原因: maxRows制限
- split_laps は正しく19ラップ生成していた
- 表示が少ない原因は **kpi.json の settings.maxRows = 3**
- `showAllData=True` でも選手あたり maxRows 行に制限される設計だった
- Jamie が maxRows=2 に変更していた可能性あり（報告は「2つだけ表示」）

## 修正内容

### 1. Max Rows ドロップダウンに "All" 追加
**ファイル**: `webapp/templates/kpi.html`
- `<option value="-1">All</option>` を追加

### 2. maxRows=-1 のハンドリング
**ファイル**: `webapp/app.py`
- kpi_page(): showAllData=True 時、max_rows > 0 のときだけ head() 制限
- api_export_csv(): 同上

**ファイル**: `webapp/utils.py`
- filter_by_main_kpi(): max_rows > 0 のときだけ head() 制限

### 3. デフォルト maxRows 変更
- kpi.json の settings.maxRows を 3 → 20 に変更（ローカル・EC2両方）

## 検証
```
maxRows=20, showAllData=True: 19 rows (全ラップ表示)
maxRows=-1, showAllData=True: 19 rows (全ラップ表示)
maxRows=-1, showAllData=False, training1: 15 rows (50m-100mが有効な行のみ)
```

## 注意事項
- maxRows が大きいと、多数の選手を選択した場合にページが重くなる可能性がある
- LIMIT 50000 の SQL制限は引き続き有効
